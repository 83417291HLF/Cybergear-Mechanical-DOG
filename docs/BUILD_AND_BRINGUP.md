# 编译与上机检查

## 工程入口

打开 [sizujixgou1123.uvprojx](../software/sizujixgou1123/MDK-ARM/sizujixgou1123.uvprojx)，目标 `sizujixgou1123`，芯片 `STM32F427IIHx`。

工程 XML 记录 ARMCC `V5.05 update 1 (build 106)` 与器件包 `Keil.STM32F4xx_DFP.2.17.0`。先恢复匹配环境，再考虑编译器迁移；本次未验证 ARMClang 兼容性。

1. 在 Keil 中确认编译器、器件包和包含目录可用。
2. 执行 Rebuild，处理错误并检查隐式函数声明等警告。
3. 确认固件来自当前源码；旧 `.hex`、`.axf` 和日志不能证明当前版本可构建。
4. 核对调试器、SWD 和下载配置后再下载。

工程包含 HAL/CMSIS 源码。当前没有经过验证的 CMake、GCC 或 PlatformIO 构建流程。

## CubeMX 与源码边界

`.ioc` 保存外设配置，自定义逻辑位于 `Core/Src/main.c` 和 `MDK-ARM`。重新生成代码前先提交当前版本，生成后重点检查主循环、DMA 接收入口、CAN/串口引脚、TIM2 HAL 时基和自定义源文件清单。

运行时配置采用 12 MHz HSE、168 MHz 系统时钟。Keil XML 的 CPU 描述含 `CLOCK(25000000)`，不能替代 RCC 配置。

## 修复后的上机验证顺序

先阅读[代码问题清单](CODE_WALKTHROUGH.md)。当前快照有明确缺陷，以下是修复后的验证步骤。

1. **遥控输入**：确认 RX 容量、DMA 长度、完整帧判断一致；逐通道核对中心值、方向和开关输出。关闭发射机和拔掉接收机信号均应进入确定的停机状态。
2. **单电机反馈**：检查 CAN1 ID 1–4、CAN2 ID 5–8；确认单位、方向、温度与反馈时效。抓取 CAN 帧确认没有重复发送或静默丢帧。
3. **零位**：`quadruped_init()` 会发送使能、设零位和位置控制命令。应将标定从自动上电流程中分离，按实际机构建立零位姿态。
4. **单腿悬空**：确认电机方向与机械限位，以小位移验证 IK，记录足端实际位置并对照尺寸与坐标定义。
5. **四腿支撑**：依次验证静止站立、高度切换、姿态补偿、踏步、低步幅前后和转向。人工轻微倾斜验证补偿方向。
6. **时序与故障**：记录循环耗时、发送失败数、最长反馈间隔；验证电机掉线、CAN 异常和 IMU 无效数据的处理。
